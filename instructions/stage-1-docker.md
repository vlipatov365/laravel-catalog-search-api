# Этап 1 — Docker-окружение: объяснения концепций

## Docker Compose

Docker позволяет запускать приложение в изолированном контейнере. **Docker Compose** — инструмент для описания нескольких контейнеров в одном файле (`docker-compose.yml`) и запуска их всех одной командой:

```bash
docker compose up -d
```

Без Compose каждый контейнер пришлось бы запускать вручную с кучей флагов. Compose — это декларативное описание нужного окружения.

Наши три сервиса:
| Сервис  | Образ                  | Роль                          |
|---------|------------------------|-------------------------------|
| `app`   | php:8.4-fpm-alpine     | Выполняет PHP-код Laravel     |
| `nginx` | nginx:alpine           | Принимает HTTP-запросы        |
| `db`    | postgres:16-alpine     | База данных PostgreSQL        |

## Зачем `healthcheck` на базе данных

При `docker compose up` все контейнеры стартуют одновременно. PostgreSQL не сразу готов принимать подключения — ему нужно несколько секунд на инициализацию.

Если `app` попробует подключиться раньше — получим ошибку соединения.

`healthcheck` — это команда, которую Docker периодически выполняет внутри контейнера. Пока она не вернёт успех, зависимые сервисы не стартуют.

```yaml
db:
  healthcheck:
    test: ["CMD-SHELL", "pg_isready -U ${DB_USERNAME} -d ${DB_DATABASE}"]
    interval: 5s
    retries: 5

app:
  depends_on:
    db:
      condition: service_healthy  # ждёт, пока healthcheck пройдёт
```

## Зачем php-fpm + Nginx, а не встроенный сервер

`php artisan serve` — встроенный сервер PHP, однопоточный, не предназначен для чего-либо серьёзнее быстрой демонстрации.

**php-fpm** (FastCGI Process Manager) — менеджер PHP-процессов, умеет обслуживать несколько запросов параллельно. Но сам HTTP не понимает.

**Nginx** — веб-сервер, отлично принимает HTTP, отдаёт статику сам, а динамические запросы (PHP-файлы) передаёт в php-fpm по протоколу FastCGI.

```
Клиент → Nginx (:80) → php-fpm (:9000) → Nginx → Клиент
```

Это стандартная связка для PHP в Docker и на любом хостинге.
