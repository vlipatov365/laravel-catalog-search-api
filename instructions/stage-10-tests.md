# Этап 10 — Тесты (Pest)

## Цель

Написать Feature-тесты, покрывающие основные сценарии эндпоинта `GET /api/products`.

---

## Концепции

### Что такое Pest и чем он отличается от PHPUnit?

PHPUnit — стандартный фреймворк для тестов в PHP. Тесты пишутся как классы с методами.

Pest — обёртка над PHPUnit с более чистым синтаксисом:

```php
// PHPUnit
class ProductTest extends TestCase {
    public function test_returns_200(): void {
        $this->getJson('/api/products')->assertStatus(200);
    }
}

// Pest
it('returns 200', function () {
    $this->getJson('/api/products')->assertStatus(200);
});
```

Результат одинаковый, Pest просто читается чище.

---

### Feature-тест vs Unit-тест

**Unit-тест** — тестирует один изолированный класс или метод без БД и HTTP.

**Feature-тест** — тестирует поведение через HTTP-запрос, как реальный клиент. Может обращаться к БД.

Для нашего эндпоинта нужны Feature-тесты — они проверяют всю цепочку: роут → контроллер → сервис → БД → ответ.

---

### Как работает `RefreshDatabase`?

`RefreshDatabase` — трейт, который перед каждым тестом откатывает БД в чистое состояние (через транзакцию или миграции).

Это гарантирует, что тесты не влияют друг на друга.

```php
uses(RefreshDatabase::class);
```

---

### Зачем `getJson()` вместо реального HTTP?

`$this->getJson('/api/products')` — это не реальный HTTP-запрос. Laravel запускает приложение в памяти, имитируя запрос. Это быстро и не требует запущенного сервера.

Метод автоматически добавляет заголовок `Accept: application/json`.
